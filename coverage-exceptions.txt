# 覆盖率例外登记表（`scripts/check-coverage.sh` 双向核对）
#
# 每行一条，形如 `文件:行号: 理由`。行号是 `cargo llvm-cov --show-missing-lines`
# 报出的**当前**未覆盖行。
#
# 双向核对：未覆盖而未登记 → 门禁失败；已登记却被覆盖 → 门禁失败
# （防止例外清单变成永久豁免）。因此本文件随代码改动必须同步更新。
#
# 每条例外的理由同时以 `// coverage: excluded — …` 就地写在该行就近处
# （AGENTS.md 的覆盖率门禁要求就地标注，不靠本表单点维护）。
#
# 三条合法出路是「补测试」「删掉」「登记」，而每一条登记都必须落在
# 「无法触达的兜底分支 / 进程入口 / 结构性不可达」三类里，不含业务逻辑。
# 补得了测试的（例：`flood_frame` 的应答帧映射）一律补测试，不登记。
#
# 理由的锚点由 `scripts/coverage-exceptions.sh --check` 核对（秒级，不跑 cargo）：
# 每条登记的理由必须落在同一文件里就近的 `// coverage: excluded` 标注上，
# 或该行落在 `#[cfg(test)]` 块内（测试自身的失败分支）。两者都不是的，
# 说明这条理由没有出处，登记它等于让门禁接受一条无法复核的理由。
#
# 重建口径：`scripts/coverage-exceptions.sh --rebuild` 能从就地标注重建整张表
# （先在未覆盖行上下找最近的 `coverage: excluded` 标注；找不到且该行落在
# `#[cfg(test)]` 块内的，记为「测试自身的失败分支」；两者都不是的必须人工判定）。
