项目设置 · AgentFleet

中心式 3 台已绑定 绑定设备 全局设置
这些是项目的，不是全局的 不同项目的答案不一样：个人小工具可以让管家直接合，主仓库不行； 隔离式项目只有一台设备有资格，清理策略也不能照抄全局。 这里改的只影响 AgentFleet 这个项目，别的项目不动。

这个项目的合并权

默认档 0 · 升档只能你来

档位决定管家能不能自己把分支合到主干。这是项目级设置 —— 个人小工具和主仓库不该是同一个答案。

档管家能做什么适合
档 0 当前 只能你或你预设的规则合并。管家能给判断、能推你一把，合主干要你点头 还没建立信任
档 1 管家可合并，每次合并写进总结并通知你 用过一阵，想省操作
档 2 管家可合并，仅通知，不写总结 已经信任
档 0 下的显式规则 1 条生效
cargo test 全绿 且 改动只落在 src/ → 允许自动合并
这也是人给的规则，不是管家自己判断的。所以它属于档 0， 不需要先升档。规则见 任务详情 里的验收条件。
规则可以随时删。删掉之后，档 0 就是「任何合并都要你点头」
升档只能由人操作，管家不能自己申请 管家可以说「这次我判得对不对」，但不会说「给我升档吧」。 自我扩权是这条设计里唯一不能开的口子。

不管哪一档，合并都留痕：谁合的（人 / 管家）、什么时候、哪个分支合到了哪。

隔离策略

形态决定谁有资格跑，不是偏好是约束
项目形态
中心式 · 代码在 Hub 3 台绑定设备都有资格
形态是项目的属性，不是三种产品。可以随时把隔离式转成中心式（推上去即可）， 反过来不提供 —— 把已经上传的代码真收回来，产品做不到。
形态代码在哪Hub 存什么「起点」是什么
中心式 当前 Hub 的裸仓库 全部代码 + 元数据 Hub 上的 commit
镜像式 上游 + Hub 镜像 镜像的全部代码 + 元数据 Hub 上镜像的 commit
隔离式 只在指定设备，永不出该设备 只有元数据 设备上的 commit hash，Hub 不验证内容
派活时的过滤顺序固定，不可调换 ① 任务级 allowed_devices 派活人说了算 → ② 项目级隔离策略（本页这一块）形态决定谁有资格 → ③ 调度器按能力和负载排序谁更合适。
顺序不能换：先按负载挑出最闲的那台再查约束，约束就从「必须满足」降级成了「偏好」。
隔离式项目的代价，现在就说清 改成隔离式之后，Hub 上没有代码，Hub 也不核对设备报上来的 commit 内容。 你能看到 diff（每次向设备拉取），但看不到「Hub 上的那份」—— 因为不存在那一份。这是隔离式的定义，不是缺陷。

磁盘配额与清理

三件事分开：允许多大 / 跑不跑得动 / 跑完怎么收回
这个项目在每台设备上的配额
GB
配额是设备绑定上的，不是项目上的总数 —— 同一项目在三台设备上各占 40 GB
清理策略 默认跟随全局，这里改了这个项目就不跟了
策略依赖缓存任务产物什么时候该用
保守 留 30 天 留最近 3 个做诊断 还在调这个项目，回头要看产物
平衡 全局也是这个 留 7 天 跑完即清 日常
激进 尽快清 跑完即清 设备紧张，或者项目已经稳了
产物必清，缓存才可以留 依赖性目录按 lockfile 哈希复用 —— 但 缓存不是产物。 任务产物永远跑完就清，只有缓存受上面三档影响。 依赖目录也永远不在设备间搬运：x86-64 和 aarch64 装出来的不是同一份东西。
磁盘超 90% 就不再往这台派任务 这是全局水位，不按项目改。满了不是性能问题，是任务会静默失败的问题。 真满了会变成一条待决策进 收件箱，不会自己删东西。

项目主题色

只用来区分，不影响任何行为
用在哪
用在看板卡片左侧色条、时间线和全局任务流里的项目标签、项目页页眉。 纯视觉：改它不会改变任何任务、权限或调度。
别和配色方案搞混 这里是项目的颜色，账号级共享，团队里看到的是同一个。 你自己屏幕的暗/亮和冷暖在全局设置 · 外观， 那只存在你这台设备上，改不动别人的屏幕。

归档这个项目

可取消，不是删除
正在跑的执行 不打断，跑完才归档，结果照常进待验收
待办 / 排队的任务 停止派发。仍在这个项目里，取消归档后接着走
定时任务 一并暂停。取消归档时不会自动恢复 —— 得你看一眼再开
设备上的工作目录 按上面的清理策略回收。历史记录不受影响
执行记录、失败归因、总结、轨迹 全留着。归档不是删除
看已归档的项目

没有「删除」。项目是 Hub 的真相源，删掉会让已合入的历史、失败归因、成本记录一起消失。 失败归因和排障都要靠它 —— 一个跑了十次失败的项目，比一个干净的空项目有价值。
