固定目录

这台机器上这个项目永远用这个路径
目录必须已存在，且是一个 git 仓库
这个目录里已经有什么
✓ 是一个 git 仓库，当前分支 main
✓ 最新提交 4c8e21a
✓ 有 2 个既有 worktree
为什么必须固定，不能每次挑 设备上的依赖缓存、构建缓存、编辑器配置全都挂在路径上。 路径一漂，缓存就全部失效，每次任务都要冷启动——那比不缓存还糟。 这个路径改一次，等于把那台机器上这个项目的缓存全部作废，所以改动要你明确确认。

任务怎么在这个目录里跑

目录固定 · 工作树可弃 · 缓存可复 · 产物必清
用工作树
每个任务在这个目录下开一个 git worktree（.wt/task-NNNN）
为什么不是再 clone 一份
工作树共享同一份仓库历史，第 N 个任务不多占一份；clone 每多一个任务就多一份完整历史
代价
工作树不共享 node_modules 这类构建产物。 所以依赖缓存按 lockfile 哈希复用，任务产物随工作树一起清
跑完怎么收
删掉工作树，缓存留着；不清缓存，因为缓存不是产物

磁盘配额与清理策略

配额决定允许多大，清理决定跑完怎么收回
GB

清理策略
这台机器现在就超了 device-c 已用 91%，超过「90% 就不再派新任务」这条线。 绑定能建成功，但任务会停在待办并写明原因，直到腾出空间。 磁盘满了不是性能问题，是任务会静默失败的问题，所以它参与派活前的过滤。
去看磁盘清理确认

绑定之后可以改什么

绑定是双向的：项目页和设备页都能改
想改能不能代价
换设备可以新设备要从缓存冷启动一次
换固定目录可以，但要确认这台机器上这个项目的缓存全部作废
改配额与清理策略随时可以不影响正在跑的任务，下次派活生效
解除绑定可以历史执行记录保留；这台设备上该项目的在跑任务会先被取消
完成绑定，进看板 返回上一步 绑好之后，这个项目就能派活了
