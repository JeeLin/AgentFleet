AgentFleet · Web 控制台 · M1 设计定稿 原型 · 双击即开

深色、等宽、高密度、键盘优先 —— 一套能落到 Vue 组件的契约。

本目录是设计依据，不是代码资产。全部是零依赖的 HTML/CSS/JS：没有构建、没有依赖、没有网络请求。 规范正文在 docs/design-system.md；原型的职责是把规范里那些「容易写错的地方」画出来核对。 这一版重写了交互层：焦点归焦点栈管、键位归一张表管、背后内容被 inert、 跳转后焦点有确定落点——上一版的 7 条焦点缺陷在这里都有对应的结构性修复（规范 §4.8）。

信息架构：入口是一次对话，不是一块工作区

上一版把「工作区」做成了一级页面，于是它成了可以单独打开、可以为它挑面板的容器—— 那正是设备级多资源管理台。这一版取消了这个页面，全站只有一条主线： 选机器 → 选 agent → 选路径 → 在对话里开面板。

被删掉的路由

/w/:node/:path —— 一条都没有。工作区没有地址， 所以它不可能成为目的地。这不是「暂时没做」，是架构上不存在。

四条结构性保证（可 grep 验证）
  1. 无路由 — grep -rn 'workspace' prototype/ 应当零命中
  2. 无第二父容器 — 每个面板都是 #wb 的后代，没有 portal、没有 modal 承载面板
  3. 入口在会话内 — 设备页 grep 不到任何面板字样
  4. 路径是创建期输入 — 建立后只读，不可变 ⇒ 会话无法退化成多资源句柄
本阶段刻意不做
  • 任务分发：整体推迟到 M5，不留占位页——留一个空壳入口等于在导航里承诺一件本阶段不做的事
  • git 面板：M4 时长在面板坞的同一个位置
  • 装 agent / 改定义：一键安装是 M5，Agent 目录因此是只读聚合
  • 往设备上传项目文件：路径必须已经存在于那台设备上

交互模型：焦点与键位的四条规则

上一版的 7 条可验证缺陷全部源自同一个根因：焦点散在各页面各写各的，没有统一所有权。这一版把所有权收归两份文件。

① 焦点归最内层活动容器（FocusStack）
浮层打开时背后全部 inert（浏览器原生语义：焦点、指针、辅助树三处一起管）。 关闭时焦点还给打开它的元素——Esc、点遮罩、点关闭按钮三条路都走 focusPop()，行为必然一致。 上一版 6 页宣传 ? 是死键、trapFocus 缓存过期快照，都是绕过这条规则的后果。
② 键位表即文档（KEYS）
? 面板由 keynav.js 的 KEYS 表渲染，所以「文档写的键位」与「按下会发生的键位」不可能漂移。 AF.register() 检查 act 在表里；AF.unimplemented() 在控制台列出表里有、没人实现的项—— 上一版 31 个键位 15 个死键的根因就是「表」与「实现」是两份东西。
③ 跳转后焦点有确定落点
上一版 12 个页面 0 个 autofocus、0 个 main[tabindex=-1]：跳转后焦点回到 body， 屏幕阅读器不播报新页面。现在由外壳统一做 AF.focusMain()。
④ 键位从 31 砍到 22，没有 handler 的键位不进表
砍掉的是 file:open/up/save/revert、list:expand/multi/end、palette:move/enter、 focus:cycle、escape 等死键。列表导航改为标准 listbox 模式（Tab 进容器、↑↓ 在行间走）， 不再用全局 Enter 代理。
