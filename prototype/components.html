每个基础组件并排四态（rest / hover / active / focus + disabled）、尺寸档位、 以及「什么时候不该用它」。组件契约在 docs/design-system.md §3 里一次定死， M1 实现阶段照它写 Vue 组件——本页是那份契约的可视化核对入口。

01

Button

.af-btn + --primary|--danger|--ghost|--icon|--sm|--full

一屏一个 primary。三档变体的语义是固定的三件事，不许扩展第四档： primary＝这一步的主要动作；danger＝不可逆（删、终止、覆盖）； ghost＝面板头里的次要动作。active 用 translateY(0.5px) 而不是加深—— 按下的物理感比颜色变化更容易被手指感知。

03

Checkbox / Radio / Switch

.af-check .af-switch

Checkbox 与 Switch 的分工是硬约定：Checkbox = 提交才生效（表单里的选择）， Switch = 立刻生效（设置项，无「保存」这一步）。把 Switch 用在需要提交的表单里， 用户会以为已经保存。Radio 只在 2–5 个互斥选项时用，再多就该用 Select。

checkbox
永不提供的选项也列出来但禁用：让用户知道「我们考虑过，不做」比藏起来更有信息量。
radio
switch
「自动升级」按 PRODUCT §3.1 是设备级开关（D3）；关时只能页面手动触发。

StatusDot / State / Badge

.af-dot .af-state .af-badge .af-kv

设备三态的载体。四个通道必须同时在：颜色、字形（● ○ ◐ ◌）、填充（实心/空心/走带/虚线）、 文字标签。只靠颜色是色觉障碍用户唯一的失败点；只靠形状则在 8px 缩略下失真。 凡是「离线 / 重连中」这两种离开正常的态，一律必须带文字——「在线」可以只留点。

Tabs

.af-tabs .af-tab[aria-selected]

只用于「同一份数据的不同切面」，不用于切面板。 terminal / files 是空间并置而非互斥视图——放进 tabs 等于一次只能看一个， 直接把分栏的意义取消了（这是规范 §7 决断①的直接推论）。

07

Table

.af-table + --compact + [aria-selected] [data-inert]

两档密度共用一套表结构：紧凑 26px（设备列表、日志、快捷键）、标准 34px（需要副信息的表）。 行高必须是偶数 + 行线 1px，否则奇偶行底色交替时出现半像素错位。 data-inert 那一行「降亮但不禁用」：离线设备的行仍然可选中、可复制 node_id 与路径， 只是按钮不响应——这正是「状态不对」该有的样子。

Tree

.af-tree__row + [data-blocked] [aria-selected]

行高 22px——这是「一屏 40 个文件」的门票（60px 的树只能显示 15 行）。 被排除的节点照常显示，用斜纹底 + 删除线 + ⊘ 标出「进不去」： 隐藏它们会让用户以为树不完整，而「为什么这个进不去」恰恰是约束 3 要求被看见的东西。 灰度到读不出来的程度就失败了，所以这里的灰是 fg-disabled（2.4:1）叠加一层 5% 红斜纹—— 形状还在，文字仍可读。

Toast

.af-toast[data-tone][data-sticky]

三种生命期对应三种语义，不许可有第四种： 瞬时成功 → 2.5s 自动消失（role="status"）；可恢复失败 → 不自动消失， 必须有「重试」动作（role="alert"，可 Tab 到）；阻断性错误（越界、只读态写入） → 不许用 toast，就地横幅 + 持久条——toast 会消失，而用户还没看完。

Modal / 焦点陷阱

.af-scrim .af-modal[role=dialog]

Modal 只用于「不回答就不能继续」的事：确认不可逆动作、一次性 token、退出工作区。 普通表单与筛选一律用页面——modal 里的上下文只有它自己，键盘用户失去位置感。 焦点陷阱是硬要求：Tab 在 modal 内循环，关掉后焦点回到打开它的那个元素（keynav.js 里的浮层栈就是干这个的）。

EmptyState

.af-empty

Tooltip

.af-tip + [data-place]

只作补充，绝不承载唯一信息。键盘用户不会停在上面，所以「不看它就不知道」的内容必须 同时出现在正文或 aria-label。禁用控件有真问题：disabled 元素不派发鼠标事件， tooltip 永远弹不出来——所以套一层 wrapper 承担 hover/focus， 而不是把按钮改成 aria-disabled（那样键盘能聚焦却点不动，更糟）。

宽度按内容自适应，上限 260px；文案用短句，不超过两行。 靠 wrapper 触发：禁用原因必须同时在正文里，不能只靠这里。 同一动作也可以按 ⌃⏎。
延迟：hover 400ms 出、100ms 收；键盘焦点立即出（键盘用户没有「悬停」这个动作，等延迟等于惩罚）。 所有 tooltip 内容也要出现在 ? 键位面板或正文里。
14

Kbd / 键位表

kbd / .af-kbd

键帽是「键盘优先」的可发现载体：出现的每个键都必须在 ? 面板里查得到， 面板内容由 keynav.js 的 KEYS 表渲染——一处改动两处同步，不可能漂移。 修饰键一律用符号（⌃ ⇧ ⌥ ⏎）而不是文字（"Ctrl"）， 因为它们在按钮上只占 18px。

Splitter + 尺寸轨道

.af-split .af-gutter .af-track

视觉把手 5px、命中区 9px（::before 向外撑 4px）。 可拖 ≠ 好拖：一条精确 5px 的线在 100% 缩放的笔记本上很难点中。 把手同时是 role="separator" 的可聚焦元素——拖不了也能用键盘改布局 （方向键 32px 一档、Home 复位、⏎ 在 0.3/0.5/0.7 跳）。 悬停时露出两侧尺寸，拖拽时露出 4px 的尺寸轨道（落点预告）。

终端配色与字符

--af-ansi-* .af-term

终端是「深色里的深色」：底色 --af-inset 比外壳更深，靠 1px 描边 + 内阴影嵌进去， 不是摆进去。它用 ansi 槽位（观感优先），周围用语义槽位，两者不混用—— 所以终端像终端、周围像控制台，不会看着像「嵌了个外来物」。 每个 ANSI 前景对 --af-inset 都 ≥ 3.4:1，因为输出可能来自任意程序。

禁用清单

规范 §3.20 —— 这些组件不存在，不是「 discouraged」

「什么时候不该用」若只写成注意事项，实现阶段就会长出来。 少一个组件 = 少一次误用。下表右侧写的是「如果需求真的来了，用什么代替」。

不做为什么用这个代替
卡片流 / 瀑布流布局 控制台的内容是有结构的表与树，不是同权的图块。卡片流会把「一屏能看多少行」这个指标变成「一屏能看几张大图」。 .af-table（紧凑 / 标准两档）
折叠侧栏 / 抽屉导航 本项目的导航只有两层（分组 + 项），抽屉是为大导航设计的容器。抽屉里塞 8 个入口会让侧栏看起来像可关的装饰。 常驻侧栏 + ⌃B 折叠到 52px 图标轨（折叠后仍有悬浮标签，导航不消失）
模态表单 modal 的上下文只有它自己。带上下文的表单（选设备 + 选路径）需要页面，因为用户要参照设备列表。 页面 / 侧栏内抽屉（Panel + 固定头）
无限宽容器 + 横向滚动页面 表格横向滚动会让「设备名」那一列滚出视野——而那正是用户用来认设备的那一列。 左列 sticky + 其余横向滚动；或收敛列数
Toast 当错误通道 toast 会消失，而越界、离线、权限这类事实需要一直看得见。 就地错误块 / 面板状态条 / 持久 banner（错误类一律 role="alert"）
自动聚焦入终端 每开一个工作区就把焦点抢进终端，会让「先看文件」的流程被打断，也会让键盘用户在不知情时开始敲命令。 焦点落在窗格容器（焦点环画在窗格上），⌃B 才进终端
用主题/模式开关切浅色 双主题会让每一处「硬编码一次」的色值翻倍，且浅色版从未被验证过。深色优先是产品基调，不是默认值。 不做（若将来非做不可，先把语义槽位补全，不许在组件里写 body[data-theme=light] 分支）
纯颜色表达状态 色觉障碍、灰度打印、8px 缩略、reduce-motion —— 任一条件下都失效。 颜色 + 字形 + 填充 + 文字，四通道
同一物理键在不同页面做完全不同的事 用户要记两套映射，最终两套都记不住。 键位全局唯一（? 面板是真相源）；页面级扩展只允许在语义相同的方向上细分
把 terminal / files 做成设备级常驻标签页 约束 3 明文排除：面板绑定在会话工作区上，进入才建通道、退出即释放。设备级常驻等于把「一个 (node_id, path) 的句柄」做成设备级长驻资源。 会话工作台（session.html）
