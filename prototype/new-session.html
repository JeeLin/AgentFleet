新建会话

选设备 → 选 agent → 选工作区路径。三步都在建立会话之前定完； 路径尤其如此——它是创建期的一次性输入，建立后只读。 这个页面没有任何「打开工作区」的入口：工作区不是一个地方，是会话的属性。

  1. ①
    选设备
    哪台设备跑这个会话
  2. ②
    选 agent
    从目录里挑一个
  3. ③
    选工作区路径
    必须已经存在于那台设备上
① 设备
↑↓ 移动 · ⏎ / Space 选中
离线设备仍列出来、仍可选中：它的心跳超时（45s 判据）只说明 Hub 现在够不着它， 不说明它不该出现在候选里。选中后创建时会明确失败，而不是让用户等一个超时。
② agent
定义来自 Agent 目录，本页只读展示
候选过滤只看这台设备已装（心跳的 capabilities.agents），即「已装且就绪」， 不是「支持」。没装的标出来但仍可选——创建时会明确失败。装 agent 是 M5 的流程， 所以这里没有「安装」按钮。
③ 工作区路径
创建期输入 · 建立后只读
路径必须已经存在于上面选中的那台设备上。本阶段没有内容寻址仓库与供料 （那是 M2 的能力），建不出一个空工作区——空工作区看起来像成功了， agent 进去才发现没有项目文件，那种失败更贵。
候选路径
为什么路径只能在这里输一次 建立后不可改
会话的身份是 (node_id, path)：终端 / 文件面板的通道键、 轨迹的归属、基线与产物归档全记在这个组合上。所以路径是创建期的一次性输入， 建立之后只读。
换路径就是换一个会话——不是「把同一个会话挪个地方」。界面上没有任何地方 能改它：那会让「这条轨迹对应哪个目录」变成需要查文档才能回答的问题。
也因此没有「工作区」这个页面：它是会话的属性，不是一个能单独打开、单独浏览的容器。
取消 三项齐了才能建；缺哪项，错误就指哪一项
会话摘要
设备 未选
agent 未选
路径 未选
三项定完才建立会话。建立后不能换设备、不能换 agent、路径不可改—— 轨迹、基线与产物都记在 (node_id, path) 上。 换环境就是新会话。
装 agent 是 M5、托管覆盖层是 M2，都不在本阶段：这个页面只有「选」， 没有「装」，也没有「打开工作区」。
