通知出口

把消息送出去，不把决定带回来
先说清边界 通知是广播，看不看都行；收件箱是待办，不处理就卡住。 这两件事不能混 —— 所以邮件和 IM 只负责把消息送出去， 真正要你选的，还是回 Hub 的收件箱里选。

三个出口

站内必开，其余可选
出口状态送什么能回复吗
站内收件箱 始终开着 全部：动态 + 待决策 能。这里是决策的唯一入口
邮件 已关闭 只送动态：完成 / 失败 / 磁盘告警 / 每日摘要 不能 邮件里只有链接，点了回 Hub
IM 机器人 已开启 动态 + 能跟管家对话、审查内容 能对话、能确认管家建议； 不可逆操作给链接回 Hub
为什么邮件不能回复，IM 却能对话 邮件没有可靠的「这条回复对应哪件事」的锚点 —— 有人转发、有人改标题、有人过三天才回， 回到你手里的东西已经对不上原件了。IM 有会话上下文，能确认「你这句话是在答哪一条」。 所以对话只在 IM 开，邮件只做单向送达。

IM 机器人

连上一个群，就能在那个群里跟管家说话
一个 Hub 可以连多个，每个群一份配置
绑定到项目「AgentFleet」
出站。Hub 主动推，不开入站端口
凭据只存在 Hub，不进 agent 的上下文 webhook 地址和签名密钥进 secret 表，不写日志、不进 API 响应、不进轨迹事件。 agent 读不到它 —— 就算 agent 被提示词攻击，也偷不走这个地址。
在这个群里，什么能做、什么不能做
你想做的事在 IM 里为什么
问管家「这周做了什么」 可以 纯读取，不改任何状态
看任务进展 / 让管家解释一次失败 可以 也是读取
看一个任务的总结、验收条件 可以 聊天气泡装得下
确认「管家建议把这个任务拆成两个」 可以 管家建议不改代码、不合并，最坏结果是多一条任务， 还能在 Hub 里撤回
看一份 diff 然后决定合不合 不行 气泡里看不完一份 diff。看不完就批准，等于没审查
批准合并到主干 不行 不可逆。给链接回 Hub
确认磁盘清理 不行 不可逆，删了找不回
升合并权档位 / 删设备 不行 影响面最大的两类操作
不是技术上做不到，是刻意不做 IM 里能点「批准」，结果是你会不看就批 —— 因为气泡里放不下该看的东西。 那比「多点一次」更糟：它把审查变成了走过场，还留不下「他到底看没看」的记录。 所以不可逆操作一律回 Hub：那里有完整的 diff、失败原因和历史执行。
